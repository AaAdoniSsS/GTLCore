# 通配符样板回归

适用范围：Wildcard Pattern `0.1.2-gtl` 的条件恢复、保存顺序及固定物品编辑值保留。环境准备和依赖来源见 [开发说明](../development.md)。

## 目标行为

编辑器重建时，回填相同的示例材料应保留已选择的属性或标志。保存应先收集所有组件的当前编辑值，再序列化；每个组件每次保存只收集一次。固定物品行的未保存编辑值应在增删其他行后保留。

保留现有 NBT 格式、白名单/黑名单含义及过滤行之间的 AND 关系。示例材料显示为粉末属于原模组行为，输入输出的形态由 IN/OUT 标签决定。补丁不自动修正此前已经保存的错误过滤条件。

## 自动回归

```bash
./dev build
./dev test wildcard
./dev test wildcard --without-wildcard
```

运行测试使用独立的测试模组，通过原生 Forge 启动链调用依赖中的真实控件和保存方法。10 项用例覆盖同材料回填、更换材料、W/B 状态、保存顺序、物品/标签/流体数量、增删行、压缩 NBT 往返和样板展开。

运行器要求所有预期用例执行成功、五个 Mixin 实际应用、服务端退出码为零且世界已保存。无可选依赖模式只报告启动检查，不报告编辑器用例通过。

可以固定被测生产 JAR：

```bash
./dev test wildcard --artifact /path/to/gtlcore.jar
./dev test wildcard --without-wildcard --artifact /path/to/gtlcore.jar
```

每次实例保留 `wildcard-results.json`、控制台日志、模组来源及 SHA-256、Mixin 导出的类。检查旧基线时使用同一组断言，旧实现应因缺陷断言失败而返回非零。

## 客户端验收

在使用相同待测 GTLCore JAR 的客户端和服务端上，创建输入 `1 ingot`、输出 `1 plate` 的通配符样板，并设置：

| 类型 | 条件 | 模式 | 示例材料 |
| --- | --- | --- | --- |
| 属性 | `ingot` | W | 钢 |
| 标志 | `generate_plate` | W | 钢 |
| 标志 | `no_smashing` | B | 橡胶 |
| 标志 | `no_working` | B | 青金石 |

1. 保存后切换页面、关闭重开、增删其他过滤行；四个条件和 W/B 应保持。
2. 再次放入同材料应保留条件；换材料应正常刷新候选项。已受影响的旧样板先手动修正条件。
3. 修改固定物品、标签、流体和数量，各保存一次后重开检查；固定物品行在增删其他行后应保留编辑值。
4. 使用 1 号电路在卷板机上验证锭压板、AE 发料和成品回收，并检查应排除的橡胶、聚乙烯材料。
5. 玩家重新登录和服务端正常重启后的恢复需单独验收，并记录当时产物和环境。

自动回归通过不等于上述人工清单全部通过。记录时分别注明自动检查、客户端验收及正式部署的状态。
