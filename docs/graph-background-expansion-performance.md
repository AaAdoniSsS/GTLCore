# 图合成：后台展开与低 TPS 捕获

2026-09-24，基于 `405e0975`（已合入 `gtl-1431-skyblock` 的 `18c78140`）。

## 改动

主线程现在只捕获提供者实际样板、合法输入候选、倍率、配置物标记、返还物、声明输出和相关库存。
混合输入选择、跨槽组合、数量合并与指纹编码交给后台；没有把附属回调或实际库存提取放到工作线程。
每个样板仍最多 256 个变体，候选、变体、依赖发现及同优先级样板的顺序保持不变。

依赖发现无需先构造变体：通过截断的组合计数，以及某候选首次出现在笛卡尔积中的序号，
直接取得此前选中范围内的依赖。未进入前 256 个变体的模糊候选不会额外触发递归发现。
混合输入的后台枚举保留旧 DFS 的顺序，跳过零份额递归分支。

目录至少 512 个变体且规划线程数大于 1 时，在原有规划池中分批并行展开及编码。
每批最多 64 个样板、256 个变体，每波最多配置线程数个任务；完成后按原始顺序合并。
没有使用公共线程池，没有让工作线程阻塞等待同池任务；各分区共用取消、搜索及内存预算。
小目录仍直接在后台单个工作片内处理，避免额外调度。

## 对照方法

- 同一隔离 Forge 47.3.7 / Minecraft 1.20.1 服务端，AE 15.4.10，用户实际 ADD `3.2.8Custom_SubSpace-fix2`。
- Java 21，`-Xms2G -Xmx6G`，4 个规划线程，128 MiB 请求预算，诊断开启，无 JFR。
- 基线 JAR SHA-256：`c86339b586dcf39e8398fe3e4962de9a04b6ad43a384dcffc0d14f14532688a9`。
- 新 JAR SHA-256：`fdee681407e9abf22976fb4fe5d01f1d3c08d572b614642c75da961c104b183b`。
- 重启 JVM 后依次执行 `graphstresslarge`、`graphstress65536`、60 ms 负载的 `graphstressbusy`、
  20 ms 负载的 `graphstressloaded`、清除负载后的 `graphstressdense`、`graphstressalternatives`、
  60 ms 负载的 `graphstressalternativesbusy`。每项完成后才继续。
- 每个目标首笔单独记录；随后 1–4 次热请求不混入首笔。请求数量均为一万亿。
- 60 ms 负载通过主线程每 tick 的 park 构造，约 16 TPS，模拟没有 tick 空闲时间；
  它不是所有 CPU 核心争抢或真实重型机器负载的替代品。性能测量期间没有并行编译或其他压测。
- 每份计划在计时之后用独立物料解释器检查。普通 30 组请求同时保留 MAX_FAST 对照；
  共享图允许不同取整得到不同合法计划，65,536 层保留旧 double 字节计费比精确值少 8 的差异。
- 两组自定义变体场景共 6 次，仅对照修改前后的 Graph。该人工多槽样板的 MAX_FAST 曾触发
  30 秒测试取消，正式日志标记 `NOT_RUN_VARIANT_CAPTURE_FIXTURE`，没有冒充完成的旧算法耗时。

## 测量结果

以下是同顺序复核基线与新构建的各目标**首笔**，单位 ms；不是热缓存数字。

| 场景 | 旧整单 | 新整单 | 旧捕获经过 | 新捕获经过 |
| --- | ---: | ---: | ---: | ---: |
| JVM 启动后首个 8,192 层目标 | 513.16 | 569.53 | 123.22 | 80.27 |
| 16,384 层 | 358.83 | 311.40 | 47.01 | 42.63 |
| 32,768 层 | 588.93 | 463.24 | 80.10 | 65.55 |
| 512 × 32 共享图 | 525.13 | 516.55 | 55.97 | 86.21 |
| 65,536 层 | 1,227.19 | 970.02 | 229.35 | 165.60 |
| 每 tick 60 ms 负载，8,192 层 | 740.50 | 572.19 | 635.56 | 509.74 |
| 每 tick 20 ms 负载，8,192 层 | 132.43 | 81.06 | 19.31 | 13.54 |
| 128 层 + 8,192 种无关库存 | 2.48 | 2.59 | 0.36 | 0.33 |
| 128 个样板、32,768 个变体 | 294.21 | 139.17 | 109.69 | 7.52 |
| 同上，每 tick 60 ms 负载 | 707.49 | 108.58 | 638.32 | 64.53 |

低 TPS 变体场景整单减少 **84.7%（约 6.52 倍）**，捕获经过时间减少 **89.9%**。
主线程实际捕获工作从 19.97 ms 降至 3.54 ms，等待从 618.35 ms 降至 60.98 ms；
后台目录准备经过时间为 42.50 ms。这证明收益不只是移动计时范围。
低 TPS 精确链整单减少 **22.7%**；65,536 层减少 **21.0%**。

也有明确回退：JVM 启动后首个 8,192 层样本慢约 **11.0%**，捕获下降但目录准备经过时间为 256.44 ms。
这次测量不能证明所有冷启动都变快，也不能仅凭计时把回退完全归因于某个 JIT/GC 原因。
共享图的捕获亦有回退，整单仅小幅改善；低于 3 ms 的小用例不据此宣称明显变化。

## 计时与边界

`[Graph Crafting] snapshot_ms` 是捕获活动时间；`snapshot_elapsed_ms` 包含跨 tick 等待，
`snapshot_wait_ms` 是两者之差。`catalog_elapsed_ms` 是目录准备实际经过时间，
`catalog_parallel_ms` 是并行展开、编码任务的累计活动时间；`catalog_prepare_ms` 加总协调线程和这些子任务，
因此可能大于经过时间，不等于单线程耗时或 CPU 时间。`catalog_parallel_batches` 表明实际派发的后台批次数。
`[Graph Stress] graph_wall_ms` 测量整个请求直到 Future 完成，防止只移动计时范围就声称加速。

纯后台阶段无需等待 tick，但剩余提供者查询、谓词校验、返还物和库存读取仍由主线程执行。
每 tick 共享 2 ms 捕获额度及空闲期调度未放宽；不可抢占的外部回调仍可能超时。
这是降低主线程工作量及展开经过时间，并非保证完全不受 TPS、GC、JIT 或并发请求影响。
少量首笔和热样本不构成长时间尾延迟保证。

## 正确性检查

- 362 组独立旧枚举器差分：混合输入、跨槽组合、长数量、选择相关返还物、配置标记、上限与依赖顺序。
- 实际 AE 自定义模糊输入：未声明但有效的库存候选被捕获，无效候选拒绝；冻结后禁止所有样板/输入回调，
  清空原库存仍能在后台得到正确的 30 亿数量及两种返还容器。
- 单线程和四线程的目录、重复指纹、优先级顺序一致；取消、共享内存耗尽后不会发布不完整目录，重新请求可成功。
- 核心 25,772 个断言、执行器 178 个断言、调度回归、实际 AE 接口集成及 Mixin/格式/构建检查通过。
- 原生隔离服通过 ADD FOA 4/8 倍有效样板、30 亿输入、容器 4 入 1 返还、NBT、倍率切换后的提交前拒绝，
  以及实际通配符 264 条目/263 种样板、恢复 SCC/无种子拒绝。
- 真实 CPU 取消、异步总成晚到产物、满盘后每次接收 7 个及 NBT 守恒通过：原料 999、产物 1、仅派发 1 次。

服务端验证不包含客户端画面验收。执行器的物料预留、实际提取、派发和取消机制没有在这次拆分中改写。
