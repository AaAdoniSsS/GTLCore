# 循环并行与催化剂补造上限

新计划使用 `config/gtlcore.yaml`：

```yaml
ae2CraftingEngine: GRAPH
ae2GraphSeedPolicy: PRESERVE
ae2GraphMaxExtraCatalystCopies: 10
ae2GraphDiagnosticLogging: true
```

`ae2GraphMaxExtraCatalystCopies` 是为了加速而**额外制造的催化剂份数上限**，范围 0～4096，默认 64。
它不强制补满，也不限制借用已有库存；0 关闭额外补造，正常任务必需的最小启动种子仍可按原配方制造。
旧的未发布测试设置 `ae2GraphCatalystParallelism` / `ae2GraphCraftExtraCatalysts` 已移除。

系统用最大空闲 CPU 的协处理器数 + 1 估计并行需求，上限 4096；这只是规划提示，
实际派发仍受最后选择的 CPU、供应器、装配机、材料和供电限制。确认页面尚未选定 CPU 时不能保证提示就是最终 CPU。
任务很小时按有用工作量收缩需求，不为少量产物制造大量催化剂。

例如设置上限 10：

| 库存 | CPU 并行需求 | 原料情况 | 规划保留份数 |
| ---: | ---: | --- | ---: |
| 1 | 4 | 充足 | 4：已有 1，新增 3 |
| 1 | 16 | 充足 | 11：已有 1，新增至多 10 |
| 1 | 16 | 完成订单后只够再造 5 | 6：缩减补造，保留已有 1 + 新增 5 |
| 20 | 16 | 充足 | 使用已有 16，不额外制造 |

这些份数按每个循环启动配方所需的一组催化剂计量，可能涉及多个资源键。
实际新增材料成本、初始借用量及完成后保留数量都进入计划和验证，不只是显示计数。
在 `PRESERVE` 下，额外制造的催化剂也会在订单完成后返回。

补造不足时先保留不补造的可行计划，再在额度内进行有界缩减；这些尝试共享原请求的时间、内存和搜索预算。
每个被接受的方案仍经过完整执行序列验证。额度是启发式加速约束，不声称任意复杂循环下找到全局最快配置。
先经外部配方制造启动材料时，上限始终参照原始库存，不会在后续求解中再次获得一份补造额度。
已运行任务继续使用保存的物料和回收约定；修改配置影响新计划。

执行器允许同一循环阶段的相同配方同时在多台装配机上执行，且只花费 CPU 实际持有的输入。
待返回的催化剂不能用于新派发。不同循环阶段保留等待屏障，避免跨阶段取走其他步骤需要的物料。
普通无环计划仍使用已有依赖就绪调度。此次没有取消 CPU 的并行额度限制。

回归覆盖：上限 0/2/10、充足库存、小订单、增长环、外部制造启动材料、部分可负担补造、
部分产物回流、并行批次在途序列化/恢复、取消和真实 AE 大数量批处理。
