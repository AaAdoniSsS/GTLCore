## 执行器回归与修复

循环计划此前在每次提供者接受后等待全部产物返回，连循环前的普通多次拆解也被串行化。
同一阶段现在可以重复派发同一配方，数量受实际持有材料、CPU 和供应器额度限制；
预计返还的催化剂不等于库存，不同循环阶段仍保留屏障。
每个在途批次的产物归属参与保存、恢复和取消，没有重置或虚增预留。

同一隔离服测试台：3 个协处理器，一个供应器，五个相邻分子装配机，无加速卡；
300 钻石块、2,000 下界岩、初始 1 模板，下单 100 模板。
这一组前后均为 Java 20、未装 ADD、关闭额外催化剂制造，派发次数和最终物料相同。

| 构建 | 完成 tick | 20 TPS 折算 | 成功派发 | 使用装配机 | 最终模板 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 先前交付 D531… | 2,140 | 107.00 秒 | 178 | 1 | 101 |
| 修复并行 7E52… | 743 | 37.15 秒 | 178 | 4 | 101 |

完成时间减少 65.3%，约 2.88 倍；四种子样本为 717 tick、178 次派发、最终 104 模板。
两种子库存条件均通过钻石和下界岩两项守恒，不把游戏等待时间与执行器 CPU 时间混为一谈。
原始日志：`.local/server-parallel-before.log`、`.local/server-parallel-after.log`。

之后按用户要求切换为 Java 21.0.3 并装入 ADD。在默认自动并行需求 4、允许补造的情况下，

它额外制造了 3 份催化剂且换了运行环境，因此不拿这个数直接计算上表优化倍数。
配置语义及部分原料不足的处理见 [催化剂补造上限](graph-catalyst-configuration.md)。

## 1 亿与 30 亿物品规划

Java 21.0.3、Forge 47.3.7、AE 15.4.10、6 GiB 堆，并加载用户实际 ADD JAR。
新旧算法在同一 JVM、同一网络、同一库存、同一样板下串行执行，交替先后顺序。
旧算法为同一 Core 的 MAX_FAST。每组 1 次首次请求 + 7 次热请求，下表为热请求总耗时中位数，单位 ms。
总耗时包括主线程快照、排队等待、求解、验证和计划生成，未仅用求解时间对比旧算法全程。

| 拓扑 | 1 亿：旧 MAX_FAST | 1 亿：Graph | 30 亿：旧 MAX_FAST | 30 亿：Graph |
| --- | ---: | ---: | ---: | ---: |
| 128 层链 | 4.15 | 2.85 | 2.57 | 1.43 |
| 512 层链 | 8.67 | 5.12 | 6.39 | 4.05 |
| 2,048 层链 | 30.71 | 17.32 | 20.02 | 15.28 |
| 8,192 层链 | 74.87 | 109.67 | 69.32 | 108.94 |
| 8 层 × 8 路共享图 | 3.63 | 0.94 | 3.48 | 0.80 |

这五组两种数量的目标、投入、缺料、配方次数和 bytes 均一致；数量超过 int 未发生逐件展开、截断或栈溢出。
另外三组共享图仍因需求聚合后的取整得到不同但都合法的计划，单列保留，不冒充同工作量加速：

| 拓扑 | 1 亿：旧 / Graph ms | 30 亿：旧 / Graph ms |
| --- | ---: | ---: |
| 16 层 × 8 路 | 3.88 / 1.60 | 4.31 / 1.36 |
| 24 层 × 8 路 | 4.30 / 1.71 | 4.69 / 1.55 |
| 64 层 × 8 路 | 9.10 / 4.90 | 8.51 / 4.09 |

128 对请求的双方计划全部在计时后通过独立解释器，逐步核对库存、产量和原料上限。
这是实际服务端的规划测试，使用真实 AEProcessingPattern 和测试用 long 库存，并未实际生产 30 亿物品。
只有七个热样本，p95 等于本组最大值，不作为稳定尾延迟保证。

**极深链仍有差距。** 1 亿的 8,192 层首次请求约 4.01 秒；增大订单数量并不解决首次样板捕获问题。
30 亿那一轮同拓扑已被前一轮访问过，首次请求还需要检查提供者变化，约 3.01 秒，不能称为全新 JVM 冷启动。
主线程仍共用每 tick 2 ms 预算，不通过后台读世界、提高卡顿预算或削弱验证掩盖开销。
热请求的 8,192 层求解区间约 23～25 ms，但总耗时约 109 ms，存在快照跨 tick 等待及计划组装开销。

本轮减少重复计时/CAS、复用请求内不可变 AEKey 序列化及摘要对象，合并快照计量批次，
仍每小步检查期限和取消，仍重新读取有效样板语义。
同一 Java 20 配置的补充前后对照，1 亿 2,048 层 Graph 从 24.18 降到 15.03 ms，
8,192 层从 144.24 降到 111.71 ms；这些跨 JVM 数值不与 Java 21 主表混算。

原始日志 `.local/server-ring-add-java21-v2.log`；逐样本与失败/不等价标记保存在
`.local/graph-stress-add-java21.json`。计时包为 BEF8…，最终包只修正语言资源与构建清单；
逐项比较证实两包所有 `.class` 字节一致。

## 界面和验证边界

- 合成环使用 AE 灰色面板、原生工具栏按钮和中文标题，修正页脚位置及表头。
- 显示完整依赖图：物料与配方是不同节点；凝聚 DAG 分层，SCC 展开成显式有向环。
  自复制的去程、回程画成分开的弧线，避免两张相同物品图标之间重叠双箭头。
- 支持拖动、缩放、循环定位、悬停准确数量及 Shift 点击配方。后台布局和空间索引避免每帧扫描整张大图。
- 完整构建、25,767 项核心断言、178 项执行器断言、调度/取消、真实 AE API、Mixin 检查及格式检查通过。
  扩展批处理回归包括一次 30 亿 mB 派发、供应器容量限制和 10 亿 mB 部分返回。

没有运行无头 Minecraft 客户端；UI 验证目前是代码、几何和资源检查，最终视觉及鼠标交互仍需客户端实测。
